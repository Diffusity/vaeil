## CPU baseline, discovery and concurrency

Current [GPU documentation](https://docs.ollama.com/gpu) says Vulkan is enabled when its backend is installed, with Windows drivers often supplying it. That is not proof this Vega iGPU works. Record discovery logs before selecting any GPU path. `OLLAMA_VULKAN=0` or `GGML_VK_VISIBLE_DEVICES=-1` disables Vulkan; a discovered Vulkan device can later be selected by `GGML_VK_VISIBLE_DEVICES=<index>`. Do not install GPU software under this authorization.

For a CPU run, set process-local `OLLAMA_VULKAN=0`, `GGML_VK_VISIBLE_DEVICES=-1`, and send `options.num_gpu=0`. The [pinned API source](https://github.com/ollama/ollama/blob/v0.40.11/api/types.go) defines `num_gpu`, `num_ctx`, `num_thread`, `num_predict`, `seed` and `temperature`; GPU layers default to dynamic selection (`-1`), so record the explicit override. Check `ollama ps` reports **100% CPU** and archive server logs. `GET /api/ps` exposes loaded model digest, size_vram and context_length. [FAQ processor descriptions](https://docs.ollama.com/faq), [running-model API](https://docs.ollama.com/api/ps).

Set `OLLAMA_MAX_LOADED_MODELS=1`; use `OLLAMA_NUM_PARALLEL=2` when assessing genuine two-request concurrency, and record that setting for the concurrency-1 baseline too if the same server is retained. Parallel slots increase context memory; merely submitting two client requests to a one-slot server measures queueing, not simultaneous processing. `OLLAMA_MAX_QUEUE` bounds runtime queueing. These are experiment settings, not approved production adapter limits. [Official concurrency FAQ](https://docs.ollama.com/faq). Keep `OLLAMA_HOST=127.0.0.1:11434`; do not expose management APIs to the network. [Pinned environment configuration](https://github.com/ollama/ollama/blob/v0.40.11/envconfig/config.go).

## Non-thinking, structured output and timing

Native `POST /api/chat` accepts JSON Schema in `format`, `stream:true`, `options`, and `think:false`. Inspect `POST /api/show` thinking metadata; if absent, distinguish absence of metadata from a proven unsupported control. For Qwen3 request explicit `think:false`, inspect streamed `message.thinking` as well as content, and report rejection/unexpected thinking rather than silently comparing different modes. [Chat API](https://docs.ollama.com/api/chat), [thinking discovery and controls](https://docs.ollama.com/capabilities/thinking).

Use a monotonic client timer for first **nonempty content** chunk (TTFT) and final completion. A thinking chunk is not the first answer token. Save every raw sample/failure. Final metadata provides nanosecond `total_duration`, `load_duration`, `prompt_eval_duration`, `eval_duration`, plus prompt/evaluation token counts. Compute generation rate as `eval_count / (eval_duration / 1e9)`; client wall time remains separate. Cold load and full cold call are different columns. Schema validity does not establish label accuracy. [Chat metrics](https://docs.ollama.com/api/chat).

Pull only the exact three authorized tags. `GET /api/tags` returns their full digest, byte size, parameter_size and quantization_level; preserve these with `/api/show` and runtime version. Actual disk bytes should also be summed from manifests and referenced blobs, deduplicating shared blobs. Do not substitute library-page sizes for observed model storage. [Tags API](https://docs.ollama.com/api/tags).

## Cleanup

**Startup follow-up:** the pinned app source creates `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\Ollama.lnk` on first app startup by copying `{install}\lib\Ollama.lnk`; later starts respect deletion. The installer has no `[Tasks]` section or documented silent startup-omission flag. Therefore inspect the actual entry after installation, stop the tray, and distinguish session process cleanup from disabling future login startup; do not silently alter an existing user's startup configuration. [Pinned first-run implementation, lines35-37 and213-256](https://github.com/ollama/ollama/blob/v0.40.11/app/cmd/app/app_windows.go#L213-L256). The [official FAQ source](https://github.com/ollama/ollama/blob/main/docs/faq.mdx) recommends Task Manager's Startup apps disable control.

`ollama stop <exact-tag>` unloads a model, not the server. Quit the Windows tray application, then stop the benchmark-owned server and its runner child processes; confirm no Ollama process remains and loopback port11434 is closed. The installer source itself lists tray, ollama and llama-server process cleanup, while Windows docs explain quitting the tray for restart. Record actual stopped PIDs/paths and retain downloaded model files for the authorized installation. Do not use broad process-name killing against unrelated applications or leave a tray app to respawn the server. This operational sequence must be checked on the installed version; no claim it has been executed is made here. [Installer lifecycle source](https://github.com/ollama/ollama/blob/v0.40.11/app/ollama.iss), [Windows docs](https://docs.ollama.com/windows).
